# 仮想ノウハウ20件：共通部分構造の探索実験

実施日：2026-09-12。構造化仕様：knowhow-graph-0.1。共通辞書：core-0.1。

20件の仮想原文と構造化データを用意してプログラムを実行した結果、7種類の繰り返し構造を発見した。事前に別ファイルへ記録した期待グループ7種類をすべて回収し、この人工データ上では誤一致・取りこぼしはなかった。

**検証したのは構造化後の探索処理である。原文と構造化グラフは同じ作成者であるAIが現行仕様に沿って設計した。Bedrockへの投入や別のLLMによる自動抽出は実施していない。したがって、この結果は抽出プロンプトの精度、実データでの検索精度、異分野への転用効果を示すものではない。**

## 実験の構成

入力と評価用の正解は分離した。探索プログラムはgraphs.jsonだけを読み、原文を解析し直したり、分野名・期待グループ名で分類したりしない。原文は根拠確認と結果表示に使用する。期待グループはexpected_patterns.jsonに置き、探索完了後にevaluate.pyで照合した。

構造化データを作るbuild_dataset.pyは、今回指定した注釈を書き出すための補助スクリプトであり、任意の原文を自動で構造化する抽出器ではない。

| 項目 | 内容 |
|---|---|
| 原文 | 20件。すべて仮想・未検証の記述 |
| ノード | 174個 |
| 接続 | 156本 |
| CLAIM | 28個 |
| 探索サイズ | CLAIMが1個、または2個の連結構造 |
| 必須情報 | 引数・変化する量・量の対象・条件・LOGICの全要素を保持 |
| ENTITY | 個々の対象を一対一の変数として対応づけ、元の名前と種類を記録 |
| 意味の一致 | 概念ID、増減、predicate、否定、不確実性、文脈、値、単位、接続role・向きを保持 |
| 未登録概念 | その概念を必要とする断片を保留 |
| 実装 | Python標準ライブラリのみ。追加インストール・ネットワーク接続なし |

## 実装した探索手順

1. 出力仕様の主要な項目、参照ID、引用、辞書、接続先の型、引数の本数、LOGICの循環を検査する。これは一般的なJSON Schemaエンジンによる検証ではなく、本探索器が使う契約の検査である。
2. 各CLAIMを起点に、必要な引数・条件へ向かう接続をたどり、意味の欠けない断片を作る。無関係な独立ノードは含めない。
3. 引数を含む範囲でノードを共有するCLAIMの組から、2関係の断片も作る。因果連鎖だけでなく分岐等も同じ規則で扱う。
4. ノード数、接続数、比較用ラベルの個数、roleの個数から粗いキーを作る。
5. 同じ粗いキーの候補に対し、属性付き有向グラフの同型判定を行う。異なるroleの並列接続、同じ対象への参照、接続方向も照合する。
6. 一致した断片を代表パターンへ追加し、ノード・接続の対応表、対象の置換、原文引用を保存する。
7. 2文書以上で現れたパターンを繰り返し構造として出力する。同一文書内の反復は支持文書数を増やさない。

同型判定は候補ノードを絞った完全バックトラックで実装した。粗いキーの一致だけでは採用しない。最大共通部分グラフを任意サイズで求める実装や、gSpanの実装ではない。

## 見つかった7種類

以下の表示名は、探索完了後に期待グループとの完全一致を確認して付けた説明ラベルである。探索器へパターン名や完成形を渡したわけではない。7種類には連鎖全体とその部分が重複して含まれるため、独立した原理が7個発見されたという意味ではない。

| 検出ID | 共通構造の説明 | 支持事例 | 件数 |
|---|---|---|---|
| P002 | 追加 → 活動にかかる時間の増加 | K01, K02, K03, K04, K05, K06, K07 | 7 |
| P001 | 活動にかかる時間の増加 → 利用可能時間の減少 | K01, K02, K03, K04 | 4 |
| P003 | 追加 → 活動時間増加 → 利用可能時間減少の連鎖 | K01, K02, K03, K04 | 4 |
| P013 | 件数10以上の条件付きで、活動時間増加 → 利用可能時間減少 | K09, K11 | 2 |
| P015 | 活動時間の増加が、業務の遅れの手がかりになる | K13, K14 | 2 |
| P017 | 始動には、同じ対象の温度が80度以下であることが必要 | K16, K17 | 2 |
| P019 | 二つの活動時間がともに増加 → 利用可能時間減少 | K19, K20 | 2 |

上表は意味を短く表示している。可能性・肯定否定・記述文脈・条件はresults/strict.jsonの各パターンに保存している。例えば、時間の連鎖の2本のCAUSESはそれぞれPOSSIBLEであり、最初の行動から最終結果への直接因果は生成していない。

### 具体例：異なる4分野の連鎖

```text
対象Xの追加
  ─CAUSES / POSSIBLE→ 活動Yにかかる時間の増加
  ─CAUSES / POSSIBLE→ 活動Zに使える時間の減少
```

| 事例 | X | Y | Z |
|---|---|---|---|
| K01 | 人員 | 説明・調整 | 実作業 |
| K02 | 製品種類 | 段取り替え | 製造 |
| K03 | 予約枠 | 予約確認 | 接客 |
| K04 | 書類様式 | 照合 | 審査 |

K04には別の観察行動も加えたが、共通する連鎖は切り出せた。グラフ全体が同じである必要はない。

ただし「人員」「製品種類」「予約枠」「書類様式」を対象変数として対応づける妥当性は、プログラムの一致とは別の確認事項である。「付随作業」「時間枠の共有」「ボトルネック」等の解釈は追加していない。

| 対照 | 期待 | 実際 |
|---|---|---|
| 量の意味 | 区別 | 区別 |
| 因果の否定 | 区別 | 区別 |
| 因果と時間順序 | 区別 | 区別 |
| 可能性と断定 | 区別 | 区別 |
| 条件の有無 | 区別 | 区別 |
| 条件値10と20 | 区別 | 区別 |
| 同じ条件値10 | 一致 | 一致 |
| 兆候と因果 | 区別 | 区別 |
| 比較演算子以下と以上 | 区別 | 区別 |
| 共同条件と単独原因 | 区別 | 区別 |

K05〜K07は連鎖全体としてはK01〜K04と一致しないが、最初の「追加→かかる時間の増加」は共通する。このように、同じ事例に一致する部分と一致しない部分が混在してよい。

K12の「作業のしやすさ」はcore辞書にないため、その量を必要とする断片を保留した。nullを共通概念にして他の量とまとめる処理は行っていない。

## 属性を落とす比較実験

同じ35個の探索可能な断片を基礎とし、比較時に一部の情報を意図的に落とした。no_conditionsでは条件への接続とその専用部分も比較用グラフから外した。未知概念の保留条件はすべての方式で共通にした。

**評価の「組」は、異なる文書にある二つの断片の組であり、文書全体のペアではない。** 同じ期待グループに属する断片間の37組を正の対応とし、予測したグループ内の対応と比較した。ここでの全組照合は評価のためであり、探索器へ正解を教える処理ではない。

| 比較方式 | 正しく回収 | 誤一致 | 取りこぼし | 適合率 | 再現率 |
|---|---:|---:|---:|---:|---:|
| 意味・条件を保持（採用案） | 37 | 0 | 0 | 100.0% | 100.0% |
| 概念IDを無視 | 37 | 8 | 0 | 82.2% | 100.0% |
| 否定を無視 | 37 | 1 | 0 | 97.4% | 100.0% |
| 条件を削除 | 37 | 14 | 0 | 72.5% | 100.0% |
| ノード型・role・向きだけ | 37 | 57 | 0 | 39.4% | 100.0% |
| 意味を保持し、対象の種類も固定 | 16 | 0 | 21 | 100.0% | 43.2% |

概念IDを外すと「使える時間」と「必要な時間」が混ざった。条件を削除すると、条件なし・10件以上・20件以上の断片が混ざった。形だけの比較は述語、増減、値、不確実性なども区別しないため、誤一致が増えた。

逆にENTITYの種類まで一致必須にすると、人員（GROUP）と製品種類（CATEGORY）等を含む構造が分かれ、期待対応を21組取りこぼした。この結果は対象属性を常に無視してよいという根拠ではなく、何を変数にしてよいかを明示する必要を示す。

適合率100%・再現率100%は、同じ作成者が原文・注釈・期待対応を設計した小さな統制データに対する値である。独立した評価者や実ノウハウでの精度ではない。

## プログラムの検証

19テストが通過した。

- 20件の入力仕様・参照・根拠・接続規則の検査。
- 文書順、ノードID、ノードと接続の配列順を変えても期待対応が変わらないこと。
- すべての保存済み対応表が、ノードの一対一対応と接続方向・roleを保持すること。
- 同一文書内の複製で支持文書数が増えないこと。
- 未解決の限定がある部分だけを保留すること。
- ANDの全要素保持、ANDとORの区別、否定・不確実性・述語・文脈・量・条件値の違い。
- 同じ対象への参照と、別対象への参照の区別。
- 粗いキーが同じでも非同型のグラフを区別すること。
- 2〜6ノードの80組の人工グラフについて、独立した全順列列挙による判定と一致すること。

80組の比較はマッチャーの実装検査用であり、ノウハウ原文80件を追加したものではない。

## 分かったことと、まだ分からないこと

今回確認できたのは、正規化済みの小さなグラフが与えられれば、名称が異なる事例の部分構造を機械的に集め、その根拠へ戻れること。また、概念・否定・条件を比較情報として残すことが、この統制データの誤一致を防いだこと。

まだ確認していないのは、任意の原文からこのグラフを一貫して自動抽出できるか、必要な意味を辞書が十分に覆うか、大きいグラフや1,000件での費用、実務の専門家が対応を認めるか、質問への転用に役立つかである。PREVENTSや複雑な連鎖全体のスコープなど、今回の原文20件に十分含めていない表現もある。

現行仕様で未解決の限定・範囲は保留にする。JSONが整っていることやREADYであることから、原文の解釈の正しさは保証しない。温度の「度」も原文どおり保存し、℃と推測していない。
